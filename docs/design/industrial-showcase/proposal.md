# 工业企业示例网站：对标、选题与实施计划

日期：2026-10-04。状态：方案与 A+C 首期范围及[首轮 6 张效果稿](mockups/README.md) 已获用户确认，A+C 首期实现已完成，本地验收记录见仓库根目录 `design-qa.md`；B+D 仍为后续规划。

建议规划 **4 个可独立浏览的示例网站，先完成 A「工业优选」与 C「精工制造」**。两套分别服务工业品经销商和小型制造商；再用 B「应用伙伴」与 D「产品品牌」补足不同经营模式。每套都有电脑和手机专属布局、一个完整业务体验，以及独立源码和交付目录。

本轮已检索官方站点、阅读产品与能力介绍，并在浏览器查看 Accu、PrecisionCore 首页视觉。以下方案是根据调研提出的设计判断；未对参考站进行完整手机验收或转化率测试，不以知名度推断其获客效果。图片候选及取得方式见 [素材清单](asset-plan.md)。

## 1. 我们要帮助客户做什么选择

客户不一定知道自己喜欢哪种网页风格，但通常知道：自己卖什么、买家怎么选、最需要证明什么。示例库按这些问题组织。

| 客户类型 | 买家最关心的问题 | 网站应首先解决的事 |
| --- | --- | --- |
| 多品类工业品经销商 | 有没有我要的型号？规格是否匹配？怎么询价？ | 可搜索的产品目录、清楚的参数、可汇总的询价单 |
| 提供选型服务的经销商 | 我的设备或工况该配什么？ | 从应用场景进入，解释适用条件，引导补齐需求 |
| 来图加工的小型制造商 | 能不能做？工艺与质量是否可靠？ | 加工范围、设备与样件、检验流程、加工需求清单 |
| 有自有系列产品的制造商 | 产品差异是什么？有哪些尺寸和配置？ | 系列对比、细节图、规格说明、定制选项 |

默认面向中文客户，以询盘型官网为范围；英文版可作为后续扩展。网站给客户一个能够被搜索、被转发、反复核对产品与能力的正式入口。示例库的销售文案可用：**“让客户找到产品、看懂实力，再带着明确需求联系你。”** 不承诺建站必然带来订单或搜索排名。

## 2. 可对标的网站与具体借鉴点

“优秀”在本方案中指某些信息表达或选型路径值得学习，并不表示每个页面都值得复制。大规模平台只作局部功能参考，小企业示例控制信息量与维护成本。

| 官方参考 | 已核实的内容 / 优点 | 用在哪套示例 | 图片参考与适配边界 |
| --- | --- | --- | --- |
| [Accu](https://www.accu.co.uk/) | 尺寸、材质、类型等搜索入口突出；零件分类、快速下单和定制制造入口明确。浏览器实看为深蓝导航、白色搜索区、醒目产品宣传图 | A：搜索优先、统一产品卡、产品分类 | 零件抠图和分类图可参考拍摄构图；没有取得其图片使用授权。只取目录组织方式，不照搬大型电商的账户、支付、库存系统 |
| [Tameson](https://tameson.com/) | 阀门、气动、管件等目录之外，还有选型指南、应用示例、技术支持入口 | A：参数组织；B：应用到产品的路径 | 产品与应用图片丰富，授权未确认。适合借鉴“产品 + 技术解释”，不将技术推荐包装成自动工程结论 |
| [PrecisionCore Manufacturing](https://www.precisioncoremfg.com/) | 官方自述为小型独立加工厂；列出 CNC、3D 打印、设备与材料能力，并区分内部与协作服务。实看首页采用黑橙色、加工大图和报价按钮 | C：最贴近小厂经营方式的主参考 | 工艺特写构图值得借鉴；图片授权未确认，不复制其设备、资质和产能为示例企业事实 |
| [Edmar Engineering](https://edmarengineering.co.uk/) | 家族经营，明确讲小批量、原型、单件与工装；加工服务范围直接 | C：内容取舍与小批量定位 | 作为业务范围参考，非主要视觉标杆；未核实员工规模，不据此认定法定小微企业 |
| [Komaspec](https://www.komaspec.com/) | 将工艺、组件/成品、质量、从设计到交付的流程连接起来，有工厂与装配图片 | C：从能力到交付证据的叙事 | 企业规模高于目标小厂，仅借鉴流程表达；不可照搬全球工厂、人员、产量或客户背书 |
| [Hammond：Small Enclosures](https://www.hammfg.com/electronics/small-case) | 外壳按类型分组，支持尺寸、材质、颜色等筛选 | D：系列产品与规格入口 | 产品信息结构参考；不是小企业规模参考，也不是本方案极简视觉的直接来源。型号图与图纸仍需授权 |

从这些网站提炼的方向是：经销商优先帮助买家“找到并核对”，制造商优先帮助买家“判断能否交付”。每套的色彩、摄影、版式为本项目重新设计。

## 3. 四套示例的设计方案

下列名称是方案代号，不作为已注册企业名称。页面持续显示“虚构企业 · 网站设计示例”。

### A「工业优选」——蓝白、清晰、高效率

**对象：** 轴承、紧固件、传动配件经销商。示例先聚焦 3 个品类，避免做成空泛的“什么都卖”。

- **视觉：** 白底、海军蓝标题、钴蓝按钮、浅灰分区；产品照片统一浅色背景，细线分隔与紧凑参数排版。建议色板 `#FFFFFF / #142B49 / #245BDB / #EEF2F6`。
- **首页：** 型号/关键词搜索 → 3 类产品 → 常见选型入口 → 代表产品 → 采购支持 → 整理询价清单。首屏不放遮挡产品入口的大型视频。
- **电脑：** 目录页左侧筛选、右侧产品网格；详情页产品图与关键参数并排。
- **手机独立设计：** 顶部紧凑搜索框，分类双列；列表改为单列“缩略图 + 型号 + 3 项参数”。筛选从底部抽屉展开，保留已选条件及结果数量；底部显示询价清单数量。长参数表转换为分组键值信息。
- **关键体验：** 本地搜索/筛选 → 查看详情 → 加入清单 → 修改数量 → 生成、复制询价摘要。空结果与清空条件均可操作。
- **示例文案：** “按型号找产品，按参数选配件。”
- **素材目标：** 12 个示例产品记录、至少 6 张不重复产品图、3 张分类图、1 张仓储场景图。图像未匹配具体型号时标注“品类示意”，不假装实物一致。

### B「应用伙伴」——青绿、场景化、顾问式

**对象：** 气动元件、流体控制配件等兼具选型服务的经销商。

- **视觉：** 米白背景、深青绿文字、青绿强调色；设备应用摄影与简洁线路图，留白多于 A。建议色板 `#F5F5EF / #123F3C / #167D72 / #E0E9E3`。
- **首页：** “你要解决什么问题” → 3 个应用场景 → 对应产品组合 → 选型沟通步骤 → 技术文章 → 咨询入口。
- **电脑：** 场景图与问题说明并排，点击场景切换内容；场景详情连接相关产品。
- **手机独立设计：** 首屏直接提供场景卡片；选型需求分为用途、介质/环境、连接与数量三步，随时可返回修改。仅收集买家信息，不自动宣称兼容或安全适用。
- **关键体验：** 选择“包装设备气动执行”等场景 → 阅读适用信息 → 选择关注的组件 → 整理选型沟通清单。
- **示例文案：** “从你的应用出发，把选型说清楚。”
- **素材目标：** 3 张应用场景图、6 张组件图、2 张技术服务场景图、3 幅原创简化流程示意。优先使用行业场景照，人物不能冒充企业员工。

### C「精工制造」——黑橙、工艺细节、制造实力

**对象：** CNC、车铣、钣金等来图加工的小型制造商。首套聚焦 CNC 小批量零件，钣金为未来行业变体。

- **视觉：** 石墨黑、暖灰、机械橙；刀具与金属表面特写，大字号短标题、编号工艺段落。建议色板 `#151719 / #F1F0EC / #F17632 / #9A9D9E`。
- **首页：** 加工特写 + 服务定位 → 材料/工艺范围 → 样件 → 设备与检验 → 从需求到交付的步骤 → 加工需求入口。
- **电脑：** 宽幅工艺图，样件与工艺解释交错排列；参数区保持静态可读。
- **手机独立设计：** 使用独立竖幅工艺图；标题、业务范围和行动按钮放在图外保证清晰；样件纵向排列，工艺按段展开，底部只保留“整理加工需求”主按钮。移动端默认静态首图，避免连续视频和重度视差。
- **关键体验：** 看样件/能力 → 选择材料、工艺、数量与交期 → 生成加工需求清单。示例不要求客户上传真实 CAD；附件服务等真实后端确认后再实现。
- **示例文案：** “从一件样品，到稳定的小批量交付。”此为示例定位，正式客户需以实际能力审核。
- **素材目标：** 横/竖首图各 1 张、工艺照片 3 张、样件图 4 张、检验图 2 张。没有真实量测依据，不显示虚构精度、良率或认证徽章。

### D「产品品牌」——银白、极简、产品主导

**对象：** 工业机箱、仪器外壳等有固定系列、又支持尺寸与开孔定制的小型制造商。

- **视觉：** 银白背景、石墨文字、克制的深红强调；大幅单品、规整系列网格、材质细节图。建议色板 `#F6F6F4 / #22262B / #A3313D / #D8DCE0`。
- **首页：** 一个主打系列 → 系列差异 → 材质/结构细节 → 定制步骤 → 资料与联系。
- **电脑：** 产品图占首屏主视觉，系列对比采用并列表格，定制选项与图示对应。
- **手机独立设计：** 产品正面与细节分图展示；系列比较每次最多 2 款、共同字段纵向对齐；规格和资料用折叠分组，不把宽表格挤入窄屏。颜色/外观切换提供点击按钮，不依赖悬停。
- **关键体验：** 浏览 3 个系列 → 比较 2 款 → 选择示例外观/尺寸需求 → 生成咨询摘要。外观切换不等同于可制造性校验。
- **示例文案：** “标准系列，适配你的设备；定制细节，服务你的应用。”
- **素材目标：** 3 个系列、6 个款式记录、至少 6 张统一视角产品图与 3 张细节图。产品图是本套最大的素材准备项：优先原创示意渲染或授权实拍；不直接使用 Hammond 产品图。

## 4. 演示范围与页面数量

每套须能完整体验一条路径，不做只有首页可点的空壳，也不扩展成完整工业商城。重复产品详情共用该站点模板，但每条记录均须有一致、可读的示例数据。

| 示例 | 页面模板 | 内容实例范围 | 核心验收任务 |
| --- | --- | --- | --- |
| A | 首页、目录、产品详情、采购支持、询价清单（5 种） | 3 品类 / 12 产品 | 找到一个指定示例型号，筛选后加入 2 件，复制清单 |
| B | 首页、场景列表、场景详情、产品详情、选型需求（5 种） | 3 场景 / 6 组件 | 从一个场景选组件并整理沟通要点 |
| C | 首页、能力、样件列表、样件详情、加工需求（5 种） | 3 工艺内容区 / 4 样件 | 查看样件工艺，生成含数量、材料、交期的需求 |
| D | 首页、系列列表、系列详情、产品详情、定制咨询（5 种） | 3 系列 / 6 款式 | 比较 2 款后带着选择进入咨询摘要 |

公司简介、常见问题先放入现有页面，不为凑页数添加新闻中心。资料下载首期只提供原创且明确标为演示的选型/需求清单 PDF，不搬运对标企业图纸，不生成可误用于生产的技术图纸。

所有演示表单只在本机整理、复制内容，明确提示“未发送”。不接真实支付、库存、询价后端或图纸上传；不把虚构供应商询盘上报到行人易安现有需求埋点。另设明确的 **“我也要类似的网站”** 入口，返回行人易安真实联系页并带入示例代号，让客户知道自己联系的是建站服务商。

## 5. 客户如何浏览与选择

在行人易安官网增加“行业网站示例”入口，规划于自身站点 `/examples/` 页面；它不是域名根路径的固定约定，应沿用当前站点 basePath。

- 顶部提供“我是经销商 / 我是制造商”分类；每张卡片说明适合的业务、核心功能和视觉特点。
- 四张卡片同时展示桌面与手机预览；“查看完整示例”进入真正独立的网站，手机直接全宽打开，不塞进电脑模型中。
- 允许比较最多 2 套的业务适配与功能，并保留“按需组合定制”的说明。样式选择不等同于固定价格或服务套餐。
- 示例顶部使用轻量提示条，包含“设计示例”“返回示例库”“我也要类似网站”，手机避免同时叠加多条固定操作栏。
- 虚构案例不加入“真实客户案例”栏目；示例站持续 noindex，即使行人易安正式站允许索引也不自动放开示例。

## 6. 手机与性能设计标准

手机是主要交付形态之一。后续每套先提交 390px 首页及关键业务页，再与 1440px 电脑稿一同确认。设计时同步考虑 320、375、430、768、1024px 的变化。

| 内容 | 手机约定 |
| --- | --- |
| 导航 | 搜索与主业务入口优先；菜单可触控和键盘操作，打开后不挡住关闭入口 |
| 参数 | 关键参数先显示，完整参数分组；确需横向滚动的比较区提供明确提示，整页不横向溢出 |
| 表单 | 逐段填写，显式标签、必填提示与错误定位；输入错误保留已填内容 |
| 行动按钮 | 触控区域设计目标至少 44 × 44 CSS px；底部考虑安全区与软键盘，避免遮挡正文 |
| 动效 | 短距离淡入、状态切换为主；支持减少动态效果，不依赖悬停揭示核心信息 |
| 图片 | 手机单独选图/裁切，产品不变形；首图优先加载，以下图片延迟加载 |

性能预算是后续验收目标：手机首屏关键图片尽量控制在 250KB 以内，首屏总传输目标 800KB 以内，不默认自动播放视频；按固定移动端测试配置记录 LCP/CLS，目标 LCP ≤ 2.5s、CLS ≤ 0.1。实验室结果与中国大陆实际网络表现分别记录，不将本地得分当作真实用户保证。

## 7. 工程承接方式

沿用仓库已有 React / Next.js 静态导出、pnpm Workspace 和 GitHub Pages Actions 方案，不另建运行时后端。本节是后续开发约定，本轮不创建这些应用。

| 示例 | 计划源码目录 | 独立产物目录 |
| --- | --- | --- |
| A | `sites/demo-industrial-catalog/` | `dist/demo-industrial-catalog/` |
| B | `sites/demo-industrial-solutions/` | `dist/demo-industrial-solutions/` |
| C | `sites/demo-precision-manufacturing/` | `dist/demo-precision-manufacturing/` |
| D | `sites/demo-product-brand/` | `dist/demo-product-brand/` |

内容、图片、配色与页面结构留在各站内；继续共享 `packages/config`。只有在两套实现证实需要后，才抽取无品牌的筛选/清单辅助逻辑，不提前做大型通用模板引擎。

登记到 `sites.manifest.json` 后，通过现有全量构建汇总发布，不能仅上传一套覆盖其他站。每站内部链接、图片与下载资源处理自己的 basePath；跨站入口按当前发布根地址生成。新增 noindex 控制需按站点区分，并以导出 HTML 检查为准。默认搜索针对少量静态示例数据在浏览器完成，产品正文仍静态输出。

## 8. 分阶段实施与确认点

以下是工作范围估算，不是日历承诺；素材齐全、每阶段一轮集中反馈的情况下，先做 A+C 比同时铺开四套更容易控制质量。

| 阶段 | 产出 | 进入下一阶段的条件 | 参考工作量 |
| --- | --- | --- | --- |
| 0：本轮 | 6 个参考站分析、4 套选题、素材候选、实施计划 | 确认本方案与首期范围 | 已完成文档 |
| 1：视觉与素材 | A+C 各 1 张电脑首页、1 张手机首页、1 张手机关键页，共 6 张主要设计稿；确定图片与文案样本 | 你确认设计稿后才开发 | 2–3 人日 |
| 2：第一批开发 | A+C 独立可交互网站、示例库基础入口 | 两条完整演示路径可用 | 4–6 人日 |
| 3：第一批验收 | 双端截图、交互/路径/性能报告、素材记录、发布产物 | 验收通过，发布安排确认 | 1–2 人日 |
| 4：扩展第二批 | B+D 设计、开发与同标准验收 | 第一批方向有效，第二批设计确认 | 6–9 人日 |

首批估算合计 7–11 人日，四套合计 13–20 人日。真实供应商素材授权、补拍、翻译、真实表单接口接入与额外反馈轮次不包含在该估算中。若需要更快展示，先交付 A+C 的完整路径，不削掉手机稿或把关键页面做成假按钮。
