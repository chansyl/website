# 行人易安科技手机网页设计方案

本方案基于用户已选定的第 3 张“星际航线”视觉方向，为手机单独组织页面构图和访问流程。目标是让访客先看懂四项业务，再便捷地了解服务、沟通需求，同时保留紫色轨道和宇宙地平线的品牌记忆。

状态：手机视觉方案已获确认，已按后续授权实现并完成浏览器多尺寸验收，详见仓库根目录 design-qa.md。根据最新要求，文字与内容顺序采用 [官网文案](website-copy.md)，加强企业官网价值及电脑、手机体验的表达。设计参考宽度为 390px，常见参考视口为 390 × 844px；效果图展示约 390 × 1170px 的连续滚动内容，不能将整张长图视作手机一屏。效果图保留已确认构图，图中的旧文字与章节顺序在实现时按文案稿更新。

## 一 手机独立设计的变化

| 设计点 | 桌面方向 | 手机方案 |
| --- | --- | --- |
| 主标题 | 居中横向两行 | 靠左三行，让主要信息保持足够字号 |
| 轨道 | 完整大弧环绕内容 | 从右上切入的局部光弧，左侧保留安静阅读区 |
| 地平线 | 横向铺展，人物居中 | 较短的纵向场景，人物移到右侧，不占用文字区 |
| 四项业务 | 横向轨道上的四个节点 | 两列两行的大触控入口，直接显示名称和用途 |
| 导航 | 展开的顶部链接 | 品牌与菜单，菜单展开后显示大字号分组链接 |
| 主行动 | 居中按钮与次要链接 | 内容区内宽按钮；滚动离开按钮后出现底部咨询入口 |
| 交付流程 | 横向四阶段 | 纵向四阶段，概要直接显示，细节按需展开 |
| 特效 | 适度空间层次与轨道动态 | 静态宇宙画面优先，少量局部光效，不依赖指针跟随 |

宇宙画面负责吸引注意，业务名称、说明和按钮负责引导。关键内容不能被放入行星点击热点、自动轮播或需要拖动才能发现的区域。

## 二 首段与业务入口

内容顺序为：品牌和菜单 → 业务引导语 → 三行主标题 → 官网价值与双端体验短说明 → 主要咨询按钮 → 双端体验链接 → 地平线过渡 → 四项服务入口。

主标题更新为“让你的企业，”“拥有自己的”“线上主场。”。最后一行使用浅紫强调，其他文字保持冰白色。说明为“一个官网，完整呈现你的企业。电脑上看得全面，手机上用得顺手。”。实现时根据可用宽度和字体调节，不用固定换行造成小屏裁切。

四项入口分别为：

| 服务 | 简短说明 | 点击目标 |
| --- | --- | --- |
| 官网开发 | 建立品牌形象 | 官网开发详情页 |
| 定制网站开发 | 贴合业务流程 | 定制网站开发详情页 |
| APP 开发 | 打造移动体验 | APP 开发详情页 |
| 小程序开发 | 连接服务场景 | 小程序开发详情页 |

整个入口区域均可点击，箭头只是辅助提示。条目以细线分隔，名称、说明和装饰星体保持一致的阅读顺序。星体可以静止，不能让它的加载阻塞文字。

390 × 844px 参考视口下优先保证主标题、业务概述、咨询按钮与业务入口尽早出现；较短屏幕可以自然滚动。不要为了硬塞一屏缩小字号、压缩点击范围或隐藏内容。当前图像仅提供构图参考，实际折叠位置需在浏览器地址栏和真实字体下验证。

## 三 下滑后的页面顺序

手机访问顺序围绕官网价值和双端体验展开：

1. 四项服务入口，进入对应业务详情。
2. 官网价值，说明正式入口、完整介绍、统一分享和持续积累的作用。
3. 双端体验，以同一份内容展示手机和电脑的独立布局；手机状态优先，明确标注布局演示，一次聚焦一种状态。
4. 按需定制与交付流程，说明需求梳理、原型设计、开发验证、上线交付，以及双端体验如何纳入验收。
5. 公司简介和真实联系方式，以简短文字、真实渠道完成收尾。

效果长图只画到流程第三阶段的开头；正式页面仍需包含第四阶段和后续内容。没有绘入长图的区域不视为删除，也不以当前概念图的末端作为页面底部。

## 四 手机关键交互

### 导航菜单

菜单按钮拥有不小于 44 × 44px 的设计触控区域。展开为有明确关闭按钮的纵向菜单，显示“服务能力、双端体验、交付流程、关于我们、聊聊建站需求”。点击目标后收起；键盘焦点留在菜单内，关闭后回到菜单按钮。菜单打开时不叠加咨询浮层。

### 咨询入口

初始首段显示“聊聊建站需求”按钮，不同时显示底部重复按钮。当首段按钮离开可视区后，底部出现一个简洁咨询栏，保留同一个主要动作，跳转合作沟通页并允许改选服务。其他业务页使用“聊聊项目需求”。

咨询栏需要预留页面底部空间与设备安全区域，不能挡住业务入口、流程文字或页脚。联系区的主要按钮可见时收起浮动栏；进入输入状态或软键盘弹出时不遮挡输入框。减少动态效果模式下直接切换显示状态。

咨询栏未画在这张连续长图的底端，因为它是浏览器视口中的浮动状态，不是滚动内容的最后一节；后续交互验证需要单独检查其显示时机。

### 服务与流程

服务详情使用单列正文，关键交付物在前，扩展解释在后。流程四阶段的名称和一句概要默认可见，补充信息可展开，核心内容不依赖展开操作。

不要求用户横滑才能找到第四项业务，不使用鼠标悬停揭示关键文字，不添加全屏翻页或滚动锁定。

### 联系方式与需求整理

需求整理页先选服务，再写业务目标，其余字段按需要填写。保留“复制需求摘要”的准确动作名称，不模拟已提交或已收到。

若提供微信，支持可复制的微信号和二维码查看；同一台手机访问时，二维码不能成为唯一联系途径。电话、邮箱和微信均使用你后续提供的真实资料。

## 五 手机视觉与尺寸约定

| 项目 | 设计目标 |
| --- | --- |
| 页面边距 | 390px 参考宽下约 24px，小屏最低约 20px |
| 主标题 | 约 38–42px，粗体，行高约 1.15–1.25；窄屏重新断行 |
| 章节标题 | 约 26–30px，保持清晰分行 |
| 正文 | 约 16px，行高约 1.6；不把关键说明降为小字 |
| 服务名称 | 约 17–18px，文字和箭头都清楚可见 |
| 主要按钮 | 高约 52px，明显区分背景，触控区域至少 44px 高 |
| 内容间距 | 同组约 12–20px，章节约 48–64px，依内容调节 |
| 背景 | 深空黑 `#05050C`，主要文字背后保持低亮度 |
| 文字与强调 | 冰白 `#F7F6FF`、浅紫 `#D8BDFF`、次文字 `#B9B8CA` |
| 场景素材 | 手机专用纵向构图，独立裁切与压缩，不下载完整桌面大图后硬裁 |

## 六 动效与加载策略

手机保留“缓慢轨道光线 + 一次轻微内容进入 + 点击反馈”三类效果。首段先呈现完整可读静态画面，再判断是否加载增强效果；常规阅读不要求 WebGL 成功启动。

背景文字区域不闪烁，装饰场景不抢占滚动手势。离屏和页面隐藏时暂停；减少动态效果偏好下保留静态图，避免自动视差。交付流程不逐字打字，页面正文不随滚动反复隐藏。

手机主图使用独立资源尺寸；服务装饰与后续演示按需加载。避免整页自动播放视频、常驻高密度粒子或同时运行多个三维场景。性能与触控体验在实现阶段实测，当前图像无法证明加载速度或流畅度。

## 七 实现阶段的手机验收

- 在 360、390、430px 等代表性宽度，以及横屏和短屏情况下检查自然换行，无横向溢出。
- 在 Safari、Chrome 和常见内置浏览器中检查地址栏变化、安全区域、返回导航和软键盘。
- 页面放大、字体增大时，业务名、按钮及正文不裁切；不能禁止用户缩放。
- 主要路径可以单手完成：找到业务、进入详情、发起沟通；不依赖精细拖拽或 hover。
- 浮动咨询入口不遮挡内容，菜单与输入状态无浮层争抢。
- 关闭特效、减少动态效果或图形加载失败时，仍能阅读、导航和联系。
- 使用真实文本和真实字体检查首段信息位置，不能仅按生成图截图判断通过。
